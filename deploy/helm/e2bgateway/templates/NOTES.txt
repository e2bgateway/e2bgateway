⚠️  Prerequisites (agent-sandbox backend)
-------------------------------------------------------------

The agent-sandbox backend is in-cluster only and requires
agent-sandbox v1.0.11 components installed in this cluster:

  • CRDs: sandboxes.agents.x-k8s.io and
    sandboxclaims/sandboxtemplates/sandboxwarmpools.extensions.agents.x-k8s.io
  • Controller: registry.k8s.io/agent-sandbox/agent-sandbox-controller:v1.0.11
  • Router (needed for cold-start CreateSandbox with envs):
    registry.k8s.io/agent-sandbox/sandbox-router-go:v1.0.11, reachable as a
    sandbox-router-svc Service (or set config.backends[].config.gatewayName /
    gatewayNamespace / apiURL to point at yours)

See: https://github.com/kubernetes-sigs/agent-sandbox

⚠️  Scaling
-------------------------------------------------------------

{{- $storeType := dig "sessionStore" "type" "memory" (.Values.config | default dict) }}
{{- if and (or (gt (int .Values.replicaCount) 1) .Values.autoscaling.enabled) (ne $storeType "redis") }}
WARNING: replicaCount={{ .Values.replicaCount }} but config.sessionStore.type
is "{{ $storeType }}". EnvD access tokens and the sandbox->backend routing map
are then per-process: cross-replica data-plane requests will fail with 401 and
restarts invalidate all tokens. Set config.sessionStore.type=redis (with addr)
before scaling out.
{{- else }}
replicaCount={{ .Values.replicaCount }}, sessionStore.type={{ $storeType }}.
Scaling beyond one replica requires sessionStore.type=redis so envd tokens and
sandbox routing are shared across replicas and survive restarts. See
values.yaml for the Redis settings: the store carries bearer tokens, so TLS
is enforced for ANY non-loopback addr, with or without a password
(allowPlaintext is an explicit trusted-network opt-out).
{{- end }}
